# Energy Planner Mini MVP

## 1. 서비스 한 줄 설명

Energy Planner Mini는 사용자가 건물별 시간당 전력 사용량 CSV를 업로드하면 데이터 품질을 진단하고, 해당 건물 전용 XGBoost 모델을 새롭게 학습하여 향후 24시간의 전력 수요를 예측하는 웹서비스입니다.

## 2. 만드는 이유

건물마다 전력 사용 규모와 운영 패턴이 다르므로 한 건물에서 학습한 모델을 모든 건물에 공통 적용하지 않습니다. 사용자가 제공한 건물 데이터를 시간순으로 검증하고 학습하여 건물별 예측 모델을 만들고, 단순 기준 모델과의 객관적인 성능 비교를 거쳐 실제 예측에 사용할 모델을 선택합니다.

이 프로젝트는 인턴 기간에 수행한 전력 데이터 전처리와 24시간 예측 모델 개발 경험을 바탕으로, 데이터 업로드부터 품질 진단, 모델 학습, 평가, 예측, 시각화까지 연결하는 과정을 구현하는 것을 목표로 합니다.

## 3. 주요 사용자

- 건물의 전력 사용 현황과 다음 24시간의 예상 사용량을 확인하려는 담당자
- 자신의 건물 데이터가 모델 학습에 적합한지 확인하려는 사용자
- 데이터 분석과 AI 모델이 실제 서비스로 연결되는 과정을 확인하려는 포트폴리오 평가자

## 4. MVP 입력 데이터

- CSV 한 개는 건물 한 곳의 시간별 전력 사용량을 나타냅니다.
- 기본 필수 컬럼은 `timestamp`와 `kwh`입니다.
- `timestamp` 시간대 처리 규격은 `docs/data_contract.md`에서 확정한 정책을 따릅니다.
- `kwh`는 누적 검침값이 아니라 해당 시간 구간의 전력 사용량을 의미합니다.
- 최소 학습 기간과 품질 기준은 `docs/data_quality_policy.md`의 확정·잠정 정책을 따릅니다.

## 5. MVP에 반드시 포함할 기능

### 5.1 건물별 CSV 업로드

- 사용자가 건물 한 곳의 시간별 전력 사용량 CSV를 업로드할 수 있어야 합니다.
- 업로드한 파일의 이름, 데이터 기간, 행 수와 인식된 컬럼을 보여줍니다.
- 원본 CSV와 다른 건물의 데이터가 섞이지 않도록 건물별 작업 단위로 관리합니다.

### 5.2 CSV 형식 및 데이터 품질 진단

- 필수 컬럼 존재 여부와 데이터 형식을 검사합니다.
- 타임스탬프 파싱 실패, 시간 중복, 누락 시간과 시간 간격을 검사합니다.
- 전력값의 결측치, NaN·Inf, 음수값을 검사합니다.
- 0kWh는 오류로 단정하거나 자동 삭제하지 않고 별도 현황으로 표시합니다.
- 누적 검침값과 시간 구간 사용량을 구분할 수 있도록 입력 단위와 의미를 안내합니다.
- 결측값을 임의로 0으로 바꾸거나 자동 보간하지 않습니다.
- 학습에 사용할 수 없는 데이터는 구체적인 사유와 함께 사용자에게 알립니다.

### 5.3 시간순 학습·검증·테스트 분할

- 데이터를 시간 순서에 따라 Train, Validation, Test로 분리합니다.
- 과거 데이터로 학습하고 그 이후 데이터로 검증·평가합니다.
- Validation 데이터는 모델 설정과 모델 선택에 사용합니다.
- Test 데이터는 최종 성능 평가용으로 보존하고 학습, 스케일러 적합, 모델 선택에 사용하지 않습니다.
- 기간별 분할과 최소 표본은 `docs/training_spec.md`의 승인 정책을 따릅니다.

### 5.4 건물별 신규 XGBoost 모델 학습

- 업로드한 건물의 데이터로 해당 건물 전용 XGBoost 모델을 처음부터 학습합니다.
- 기존 인턴 프로젝트의 GRU 가중치를 재사용하지 않습니다.
- 입력은 과거 168시간, 출력은 향후 24시간을 기본 방향으로 사용합니다.
- 피처와 XGBoost 설정은 `docs/training_spec.md`의 승인된 첫 MVP 설정을 따릅니다.
- MVP에서는 기상정보를 기본 입력으로 사용하지 않습니다.
- 스케일러는 건물별 Train 데이터로만 적합합니다.

### 5.5 기준 모델 생성 및 비교

- 직전 24시간의 실제 사용량을 반복하는 Last-24h 기준 모델을 유지합니다.
- 168시간 전 같은 요일·시간대의 실제 사용량을 사용하는 Last-168h 기준 모델을 유지합니다.
- XGBoost와 두 기준 모델을 동일한 Validation 및 Test 조건에서 비교합니다.
- XGBoost가 항상 기준 모델보다 우수하다고 가정하지 않습니다.

### 5.6 성능 평가 및 모델 선택

- 최소한 MAE와 RMSE를 계산하고 사용자가 이해할 수 있는 설명을 제공합니다.
- 추가 평가 지표와 모델 채택 기준은 `docs/training_spec.md`의 Validation 선택 규칙을 따릅니다.
- 모델 선택은 Validation 결과를 기준으로 수행합니다.
- 선택이 끝난 후 Test 데이터에서 최종 성능을 한 번 평가합니다.
- XGBoost가 채택 기준을 충족하지 못하면 더 우수한 기준 모델을 예측 모델로 선택할 수 있어야 합니다.
- 실행하지 않았거나 검증하지 못한 결과를 성공한 것처럼 표시하지 않습니다.

### 5.7 향후 24시간 전력 수요 예측

- 선택된 모델을 사용하여 다음 24시간의 시간별 예상 전력 사용량을 생성합니다.
- 예상 총사용량, 평균 사용량, 최대 사용량과 예상 피크 시간대를 보여줍니다.
- 입력 데이터가 부족하거나 모델이 준비되지 않은 경우 임의의 예측값을 생성하지 않습니다.
- 예측값의 단위와 예측 기준 시점을 명확히 표시합니다.

### 5.8 예측 결과 시각화

- 과거 사용량과 향후 24시간 예측값을 시간 순서대로 그래프로 보여줍니다.
- Test 구간에서는 실제값과 각 모델의 예측값을 비교할 수 있어야 합니다.
- XGBoost와 Last-24h, Last-168h의 성능 비교 결과를 표 또는 그래프로 보여줍니다.
- 데이터 누락, 모델 오차와 평가 한계를 사용자가 이해할 수 있는 말로 표시합니다.

### 5.9 건물별 모델과 스케일러 보관

- 선택된 모델, 피처 스케일러, 타깃 스케일러와 모델 설정을 건물별로 구분해 저장합니다.
- 학습 데이터 기간, 피처 명세, 평가 지표와 생성 시점을 함께 기록합니다.
- 다른 건물의 모델이나 스케일러를 잘못 불러오지 않도록 식별 정보를 관리합니다.
- 사용자별 데이터·모델 격리 방식과 학습 자원 제한은 후속 구현 설계에서 확정합니다.

### 5.10 프로젝트 소개

- 기존 인턴 프로젝트의 전력 데이터 전처리와 24시간 예측 모델 개발 경험을 소개합니다.
- 기존 GRU의 외부 데이터 기술 검증과 일반화 성능 평가를 거쳐 건물별 XGBoost 신규 학습 방식으로 방향을 변경한 이유를 설명합니다.
- 회사명, 주소, 계량기 번호 등 불필요한 식별정보는 공개하지 않습니다.
- 예시 데이터를 실제 관측값이나 예측 결과처럼 노출하지 않으며, 실제 예측 전에는 준비 상태와 다음 행동만 표시합니다.

## 6. MVP 화면

1. **CSV 업로드 및 진단:** 파일 선택, 형식 검사, 데이터 기간과 품질 결과
2. **학습 및 평가:** 시간순 분할 결과, 학습 상태, XGBoost와 기준 모델 성능 비교, 선택 모델
3. **24시간 예측:** 과거 사용량, 향후 24시간 예측, 요약 수치와 피크 시간대
4. **프로젝트 소개:** 개발 배경, 모델 전략 변경 이유, 평가 방법과 한계

화면은 한국어로 제공하고 PC에서 보기 편한 구성을 중심으로 하되, 휴대전화에서도 세로로 내용을 확인할 수 있게 만듭니다.

## 7. 디자인 및 사용자 안내 방향

- 공공기관 서비스처럼 신뢰감을 주는 남색·파란색·흰색 계열을 사용합니다.
- 한전의 로고, 명칭과 화면을 그대로 복제하지 않습니다.
- 중요한 품질 결과, 학습 상태, 모델 성능과 예측 수치를 먼저 보여줍니다.
- 전문용어에는 사용자가 이해할 수 있는 짧은 설명을 함께 제공합니다.
- XGBoost가 선택되지 않더라도 실패로 숨기지 않고 기준 모델이 선택된 이유를 표시합니다.
- 모델 평가 결과는 해당 건물과 평가 기간에 대한 결과이며 모든 상황의 정확도를 보장하지 않음을 안내합니다.

## 8. 데이터 및 모델 정책

- 원본 CSV의 값을 임의로 수정하거나 결측값을 임의 보간하지 않습니다.
- 학습 피처는 예측 시점 이전에 확인 가능한 정보만 사용합니다.
- 스케일러는 Train 데이터로만 적합합니다.
- Validation 데이터에서 모델을 선택하고 Test 데이터는 최종 평가용으로 보존합니다.
- 건물마다 독립적인 모델과 스케일러를 생성합니다.
- 기존 인턴 프로젝트의 모델·스케일러·분석 결과는 연구와 비교 근거로 보존하며 덮어쓰지 않습니다.
- 사용자별 데이터·모델 격리, 업로드 보존 기간과 학습 자원 제한은 **미확정**입니다.

## 9. 개발자용 오류 및 진행 기록

오류 기록은 방문자용 기능으로 만들지 않습니다. 향후 `docs/troubleshooting.md`에서 발생일, 증상, 오류 메시지, 원인, 시도한 방법, 해결 여부와 최종 해결 방법을 관리합니다. 포트폴리오 화면에는 대표적인 문제 해결 사례만 선별해 소개합니다.

Phase별 완료 내용, 테스트 결과와 다음 작업은 `docs/development_progress.md`에서 관리합니다.

## 10. MVP에서 제외할 기능

- 실시간 계량기, 한전 계정 또는 외부 계량 시스템 연동
- 기존 GRU 가중치를 모든 건물에 공통 적용하는 방식
- 여러 건물을 동시에 학습하는 공통 XGBoost 모델
- 기존 모델의 자동 파인튜닝
- 기상 API 및 실시간 외부 데이터 연동
- 전기요금 또는 절감률 자동 산출
- 자동 설비 제어
- 상용 규모의 다중 사용자 동시 학습
- GRU 등 딥러닝 모델과의 자동 비교
- 계약종별을 반영한 공식 전기요금 계산
- 실시간 푸시·문자·이메일 알림
- 결제와 구독
- 관리자 화면과 복잡한 사용자 권한 관리

## 11. MVP 이후 확장 가능 기능

- 여러 건물 또는 계량기를 함께 관리하는 계정 기능
- 여러 건물 데이터로 학습하는 공통 모델
- 사전 학습 모델의 파인튜닝과 건물별 신규 학습 비교
- 기상 예보와 운영 일정 등 외생 변수 연동
- XGBoost와 딥러닝 등 여러 학습 모델의 자동 비교
- 계약종별을 반영한 참고용 전기요금 계산
- 월별 비용과 목표 달성률 분석
- 실제 알림 기능
- 학습 작업 분산 처리와 상용 규모의 동시 사용자 지원

## 12. 기술 방향

- 백엔드와 학습 코드는 Python을 기본으로 합니다.
- 모델은 XGBoost를 사용하고, 건물마다 24개 horizon 회귀기를 생성합니다.
- 입력 시퀀스는 과거 168시간, 출력은 향후 24시간을 기본 방향으로 합니다.
- Last-24h와 Last-168h를 항상 비교 가능한 기준 모델로 유지합니다.
- 모델 설정, 피처 명세, 스케일러와 평가 결과를 건물별 산출물로 관리합니다.
- 현재 로컬 MVP는 Python 표준 HTTP 서버와 정적 HTML/CSS/JavaScript를 사용하며, 운영용 프레임워크·작업 큐·저장소·배포 환경은 **미확정**입니다.
- 공개용 코드와 비공개 데이터·모델 파일을 분리합니다.

## 13. 미확정 사항

입력·학습 정책은 후속 명세에서 확정됐습니다. 다음 운영 항목은 PM 승인이 필요합니다.

- 사용자·건물 식별 방식과 데이터·모델 저장 구조
- 업로드 파일과 학습 산출물의 보존 및 삭제 정책
- 파일 크기, 학습 시간과 동시 학습 수에 대한 자원 제한
- 웹 프레임워크, 비동기 학습 방식과 배포 환경

## 14. MVP 완료 기준

다음 조건을 모두 만족하면 첫 버전이 완성된 것으로 봅니다.

- 사용자가 건물 한 곳의 시간별 전력 사용량 CSV를 업로드할 수 있습니다.
- 필수 컬럼, 시간 간격, 중복, 결측, 음수와 NaN·Inf를 검사하고 결과를 표시합니다.
- 데이터가 확정된 규격과 최소 기간을 충족하는지 판정합니다.
- 데이터를 시간순 Train, Validation, Test로 분리하고 각 기간을 표시합니다.
- Train 데이터로만 건물 전용 XGBoost를 학습합니다.
- Last-24h와 Last-168h 기준 모델을 동일한 평가 구간에서 비교합니다.
