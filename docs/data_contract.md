# Energy Planner CSV 입력 규격

## 1. 문서 목적과 적용 범위

이 문서는 Energy Planner MVP에 업로드할 건물별 시간당 전력 사용량 CSV의 입력 계약을 정의합니다. 시스템은 이 규격에 따라 파일 형식, 시각, 단위와 기본 데이터 품질을 검사합니다.

- CSV 한 개는 건물 한 곳의 데이터만 포함합니다.
- 전력 데이터의 주기는 실제 경과시간 기준 1시간입니다.
- 필수 컬럼은 `timestamp`와 `kwh`입니다.
- 기상정보는 MVP 입력으로 사용하지 않습니다.
- 원본 CSV의 값과 행을 임의로 수정하지 않습니다.
- 결측값을 자동 보간하거나 0으로 대체하지 않습니다.
- 이 문서는 입력 규격만 정의합니다. 학습 가능 여부를 결정할 결측 허용률과 최소 기간 등은 후속 단계에서 확정합니다.

## 2. CSV 기본 형식

### 2.1 파일 형식

| 항목 | 규격 |
|---|---|
| 파일 형식 | 쉼표로 구분한 CSV |
| 파일 인코딩 | UTF-8 또는 UTF-8 BOM |
| 첫 번째 행 | 컬럼 헤더 |
| 필수 컬럼 | `timestamp`, `kwh` |
| 데이터 범위 | 한 파일당 건물 한 곳 |
| 데이터 순서 | `timestamp` 기준 오름차순 |
| 시간 간격 | 실제 경과시간 기준 정확히 1시간 |
| 소수점 기호 | 마침표(`.`) |

- 필수 컬럼명은 소문자 `timestamp`와 `kwh`를 정확히 사용합니다.
- 컬럼명이 중복되거나 빈 컬럼명이 있으면 입력 오류로 처리합니다.
- CSV 표준에 따라 쉼표나 줄바꿈을 포함하는 텍스트 값은 큰따옴표로 감쌀 수 있습니다.
- 데이터 중간의 완전히 빈 행은 허용하지 않습니다.

### 2.2 필수 컬럼

| 컬럼 | 형식 | 필수 조건 | 의미 |
|---|---|---|---|
| `timestamp` | ISO 8601 날짜·시각 문자열 | 비어 있지 않아야 함 | 1시간 소비 구간의 시작 시각 |
| `kwh` | 유한한 0 이상의 숫자 | 비어 있거나 NaN·Inf·음수이면 안 됨 | 해당 1시간 구간에서 소비한 전력 에너지량 |

`kwh` 입력 예:

- 허용: `0`, `0.0`, `12`, `12.375`
- 허용하지 않음: `-1.2`, `NaN`, `Inf`, `12kWh`, `1,234.5`

0kWh는 자동으로 오류 또는 결측으로 판단하지 않습니다. 시스템은 0값의 개수와 비율을 품질 진단에 표시합니다.

### 2.3 추가 컬럼

- 필수 컬럼 외의 추가 컬럼은 허용합니다.
- 추가 컬럼은 원본 파일에 그대로 존재하지만 MVP의 품질 판정, 모델 학습과 예측 입력에는 사용하지 않습니다.
- 추가 컬럼이 `timestamp` 또는 `kwh`와 대소문자만 다른 이름을 사용하면 혼동을 막기 위해 오류로 처리합니다.
- 추가 컬럼이 있어도 기상정보나 다른 외부 변수를 자동으로 학습 피처에 포함하지 않습니다.
- 시스템은 인식한 추가 컬럼 이름을 사용자에게 보여주고 “MVP 학습에서 사용하지 않음”이라고 안내합니다.

## 3. timestamp 규격과 시간대 정책

### 3.1 우선 지원 형식

시간대 오프셋을 포함한 ISO 8601 형식을 우선 지원합니다.

| 형식 | 예 |
|---|---|
| `YYYY-MM-DDTHH:MM:SS+HH:MM` | `2026-01-01T00:00:00+09:00` |
| `YYYY-MM-DDTHH:MM:SS-HH:MM` | `2026-07-01T08:00:00-04:00` |
| `YYYY-MM-DDTHH:MM:SSZ` | `2026-01-01T00:00:00Z` |

- 1시간 단위 데이터이므로 분과 초는 `00:00`이어야 합니다.
- 한 파일 안에서 오프셋 포함 시각과 오프셋 없는 시각을 혼용할 수 없습니다.
- 오프셋 포함 시각은 UTC 시각으로 변환한 뒤 중복과 1시간 연속성을 검사합니다.
- UTC 변환값은 검사용 내부 표현이며 원본 `timestamp` 문자열을 덮어쓰지 않습니다.

### 3.2 오프셋이 없는 CSV

`2026-01-01T00:00:00` 또는 `2026-01-01 00:00:00`처럼 오프셋이 없는 시각도 조건부로 지원합니다.

오프셋이 없는 경우 업로드 화면 또는 별도 입력 단계에서 IANA 시간대 이름을 반드시 선택해야 합니다.

허용할 시간대 입력 예:

- `Asia/Seoul`
- `Europe/London`
- `America/New_York`

`KST`, `EST`, `CST`처럼 의미가 여러 개인 약어와 단순 국가명은 허용하지 않습니다.

오프셋 없는 CSV에 적용할 원칙:

1. 사용자가 선택한 시간대는 원본 파일과 별도의 업로드 메타데이터로 관리합니다.
2. 시스템은 해당 시간대를 적용해 각 행의 실제 시각을 계산합니다.
3. 시간대를 선택하지 않으면 학습 단계로 진행하지 않습니다.
4. 선택한 시간대에서 존재하지 않거나 두 번 존재하는 현지 시각은 시스템이 임의로 결정하지 않습니다.
5. 모호한 시각이 있으면 오프셋을 포함한 ISO 8601 형식으로 다시 제출하도록 안내합니다.

### 3.3 DST 처리 원칙

DST가 있는 지역에서는 현지 시계가 봄에 한 시간을 건너뛰거나 가을에 같은 시각을 두 번 표시할 수 있습니다.

- 연속성은 현지 시계의 표시값이 아니라 UTC로 환산한 실제 경과시간을 기준으로 검사합니다.
- 봄철 DST 전환으로 현지 시각 한 시간이 표시되지 않더라도 UTC 기준 간격이 1시간이면 데이터 누락으로 판단하지 않습니다.
- 가을철 같은 현지 시각이 반복되더라도 서로 다른 오프셋이 명시되어 있고 UTC 시각이 다르면 정상적인 두 구간으로 인정합니다.
- 오프셋 없는 현지 시각이 DST 전환으로 모호하거나 존재하지 않으면 해당 시각을 자동 보정하지 않고 입력 오류로 처리합니다.
- 동일한 UTC 시각으로 환산되는 행이 둘 이상이면 중복 시각 오류입니다.

예를 들어 `2026-11-01T01:00:00-04:00`과 `2026-11-01T01:00:00-05:00`은 현지 표시 시각은 같지만 실제 시각이 다르므로 중복이 아닙니다.

## 4. 단위와 시각의 의미

### 4.1 시간 구간

`timestamp`는 소비 구간의 **시작 시각**입니다.

`timestamp = 2026-01-01T09:00:00+09:00`, `kwh = 12.4`인 행은 `09:00:00 이상 10:00:00 미만`의 한 시간 동안 12.4kWh를 소비했다는 뜻입니다.

종료 시각을 기록한 CSV는 MVP 규격으로 직접 지원하지 않습니다. 사용자가 원본 데이터의 의미를 확인해 구간 시작 시각 형식으로 준비해야 하며, 시스템이 시각을 자동 이동하지 않습니다.

### 4.2 kW와 kWh

| 단위 | 의미 | MVP 입력 여부 |
|---|---|---|
| kWh | 일정 구간 동안 소비한 에너지량 | 입력 단위 |
| kW | 특정 시점 또는 구간의 평균·순간 전력 | 직접 입력하지 않음 |

정확히 한 시간인 구간에서는 평균 전력의 수치와 소비 에너지량의 수치가 같아 보일 수 있지만 단위와 의미는 다릅니다. `kW` 데이터를 컬럼명만 `kwh`로 바꾸어 제출하면 안 됩니다.

### 4.3 누적 검침값

MVP는 계량기 설치 이후 계속 증가하는 누적 검침값을 입력으로 지원하지 않습니다.

| timestamp | 잘못된 누적값 예 |
|---|---:|
| `2026-01-01T00:00:00+09:00` | 10234.1 |
| `2026-01-01T01:00:00+09:00` | 10246.5 |
| `2026-01-01T02:00:00+09:00` | 10257.2 |

위 값이 각 시간의 소비량이 아니라 누적 계량값이라면 잘못된 입력입니다. 시스템은 사용자가 데이터 유형을 “시간 구간 소비량”으로 확인하도록 요구합니다. 값이 계속 증가한다는 사실만으로 누적 검침값을 완벽하게 판별할 수 없으므로, 의심 패턴은 경고하고 사용자 확인 없이 자동 차분하지 않습니다.

## 5. 정상 CSV 예시

### 5.1 한국 시간대와 오프셋을 포함한 데이터

| timestamp | kwh |
|---|---:|
| `2026-01-01T00:00:00+09:00` | 12.4 |
| `2026-01-01T01:00:00+09:00` | 11.8 |
| `2026-01-01T02:00:00+09:00` | 10.9 |

- 각 행에 `+09:00`이 명시되어 별도 시간대 선택이 필요 없습니다.
- 실제 경과시간은 1시간이며 각 timestamp는 구간 시작 시각입니다.

### 5.2 UTC 오프셋을 포함한 데이터

| timestamp | kwh |
|---|---:|
| `2026-07-01T08:00:00-04:00` | 25.1 |
| `2026-07-01T09:00:00-04:00` | 26.7 |
| `2026-07-01T10:00:00-04:00` | 27.3 |

- 각 행에 오프셋이 명시되어 별도 시간대 선택이 필요 없습니다.
- UTC 변환 후 중복과 1시간 연속성을 검사합니다.

### 5.3 별도 시간대가 필요한 데이터

| timestamp | kwh |
|---|---:|
| `2026-01-01 00:00:00` | 12.4 |
| `2026-01-01 01:00:00` | 11.8 |
| `2026-01-01 02:00:00` | 10.9 |

- CSV에 오프셋이 없으므로 사용자가 `Asia/Seoul` 같은 IANA 시간대를 별도로 선택해야 합니다.
- DST 전환으로 모호하거나 존재하지 않는 현지 시각이 있으면 오프셋 포함 형식으로 다시 제출해야 합니다.

## 6. 잘못된 CSV와 사용자 오류 메시지

| 오류 코드 | 잘못된 사례 | 판정 원칙 | 사용자 메시지 제안 |
|---|---|---|---|
| `CSV_REQUIRED_COLUMN_MISSING` | `timestamp` 또는 `kwh` 없음 | 업로드 거부 | “필수 컬럼이 없습니다. 첫 행에 timestamp와 kwh 컬럼을 포함해 주세요.” |
| `CSV_TIMESTAMP_PARSE_ERROR` | `2026/13/40 25:00` | 해당 시각을 해석할 수 없음 | “해석할 수 없는 timestamp가 있습니다. ISO 8601 형식과 오류 행을 확인해 주세요.” |
| `CSV_TIMEZONE_REQUIRED` | 오프셋 없는 시각이며 시간대 미선택 | 실제 시각을 결정할 수 없음 | “timestamp에 오프셋이 없습니다. 건물의 IANA 시간대를 선택해 주세요.” |
| `CSV_DST_AMBIGUOUS_TIME` | 오프셋 없는 가을철 반복 시각 | 어느 실제 시각인지 결정할 수 없음 | “DST 전환으로 중복되는 현지 시각이 있습니다. 각 행에 UTC 오프셋을 포함해 다시 제출해 주세요.” |
| `CSV_DST_NONEXISTENT_TIME` | 오프셋 없는 봄철 비존재 시각 | 실제로 존재하지 않는 현지 시각 | “DST 전환으로 존재하지 않는 현지 시각이 있습니다. 원본 시각과 시간대를 확인해 주세요.” |
| `CSV_DUPLICATE_TIMESTAMP` | UTC 환산 후 같은 시각이 두 번 존재 | 중복 시각 허용 안 함 | “동일한 실제 시각의 행이 중복되었습니다. 중복 timestamp와 원본 계량 기록을 확인해 주세요.” |
| `CSV_KWH_INVALID` | 빈 값, 문자, NaN, Inf 또는 음수 | 유한한 0 이상의 숫자가 아님 | “kwh에 비어 있거나 유효하지 않은 값이 있습니다. 0 이상의 숫자인지 확인해 주세요.” |
| `CSV_CUMULATIVE_READING_UNSUPPORTED` | 시간 소비량 대신 누적 검침값 | MVP 입력 범위 밖 | “누적 검침값은 지원하지 않습니다. 각 1시간 구간의 소비 에너지량(kWh)을 준비해 주세요.” |
| `CSV_INTERVAL_NOT_HOURLY` | 30분, 2시간 또는 불규칙 간격 | 실제 경과시간이 1시간이 아님 | “timestamp 간격이 1시간이 아닌 구간이 있습니다. 오류 구간을 확인해 주세요.” |
| `CSV_TIMESTAMP_NOT_SORTED` | 시각이 오름차순이 아님 | 시스템이 원본 행을 자동 재정렬하지 않음 | “timestamp가 시간순으로 정렬되어 있지 않습니다. 원본 시각을 확인한 후 오름차순으로 준비해 주세요.” |
| `CSV_MIXED_TIMEZONE_FORMAT` | 일부 행만 오프셋 포함 | 한 파일에서 시각 기준 불일치 | “오프셋 포함 형식과 미포함 형식이 섞여 있습니다. 하나의 timestamp 형식으로 통일해 주세요.” |
| `CSV_MULTIPLE_BUILDINGS` | 한 파일에 여러 건물의 행 포함 | 한 파일당 한 건물 원칙 위반 | “한 CSV에는 건물 한 곳의 데이터만 포함할 수 있습니다.” |

오류 메시지에는 가능한 경우 오류 행 번호, 문제 값, 최초 발생 시각과 전체 발생 건수를 함께 표시합니다. 시스템은 오류를 숨기기 위해 행을 삭제하거나 값을 변경하지 않습니다.

## 7. 입력 검사 결과의 구분

| 수준 | 의미 | 예 |
|---|---|---|
| 오류 | 규격을 해석할 수 없어 다음 단계로 진행할 수 없음 | 필수 컬럼 누락, 시각 파싱 실패, 음수 kWh |
| 경고 | 입력은 해석했지만 사용자 확인 또는 후속 기준이 필요함 | 0kWh 비율, 누적 검침값 의심 패턴, 누락 시간 |
| 정보 | 입력 특성을 알리기 위한 요약 | 기간, 행 수, 추가 컬럼, 선택 시간대 |

누락 시간이 발견되더라도 허용률과 최대 연속 결측 기준이 아직 확정되지 않았으므로 이 단계의 문서에서는 학습 가능 여부를 최종 판정하지 않습니다. 누락 구간을 기록하고 후속 품질 정책에 전달합니다.

## 8. 원본 보존 원칙

- 업로드한 원본 CSV는 값, 시각과 행 순서를 임의로 변경하지 않습니다.
- UTC 변환 시각, 진단 결과와 향후 파생 피처는 원본과 구분된 내부 데이터로 관리합니다.
- 결측값을 0으로 대체하거나 자동 보간하지 않습니다.
- 누적 검침값을 자동 차분하여 시간별 사용량으로 바꾸지 않습니다.
- 오류가 있는 행을 자동 삭제하지 않습니다.
- 사용자가 수정된 파일을 다시 제출하는 경우 기존 원본과 별개의 업로드로 취급합니다.
