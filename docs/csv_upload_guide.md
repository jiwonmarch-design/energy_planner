# Energy Planner CSV 업로드 안내

이 문서는 Energy Planner에서 형식 오류 없이 전력 사용량 CSV를 업로드하기 위한 사용자 안내서입니다. CSV 형식을 통과하더라도 데이터 기간, 누락 구간 또는 장기 상수값에 따라 품질 진단은 `WARNING`이나 `FAIL`이 될 수 있습니다.

## 1. 가장 안전한 CSV 형식

| 항목 | 요구사항 |
|---|---|
| 파일 형식 | 쉼표로 구분한 `.csv` |
| 인코딩 | UTF-8 또는 UTF-8 BOM |
| 최대 크기 | 25MB |
| 건물 수 | 파일 하나당 건물 한 곳 |
| 필수 열 | `timestamp`, `kwh` |
| 시간 간격 | 1시간 단위 |
| 행 순서 | 오래된 시각부터 최신 시각까지 오름차순 |
| 권장 기간 | 180일 이상 |

첫 번째 행의 컬럼명은 아래처럼 소문자로 정확히 작성합니다.

```csv
timestamp,kwh
```

## 2. 복사 가능한 정상 예시

### 방법 A: 시간대 오프셋이 없는 한국 현지 시각

CSV:

```csv
timestamp,kwh
2026-01-01 00:00:00,12.4
2026-01-01 01:00:00,11.8
2026-01-01 02:00:00,10.9
2026-01-01 03:00:00,10.5
2026-01-01 04:00:00,10.2
```

업로드 화면 설정:

- 건물의 시간대: `Asia/Seoul`
- CSV의 시간 표기 방식: `시간대 정보가 없는 현지 시각`

### 방법 B: 각 시각에 UTC 오프셋 포함

CSV:

```csv
timestamp,kwh
2026-01-01T00:00:00+09:00,12.4
2026-01-01T01:00:00+09:00,11.8
2026-01-01T02:00:00+09:00,10.9
2026-01-01T03:00:00+09:00,10.5
2026-01-01T04:00:00+09:00,10.2
```

업로드 화면 설정:

- 건물의 시간대: 실제 건물의 IANA 시간대(한국은 `Asia/Seoul`)
- CSV의 시간 표기 방식: `CSV에 포함된 UTC 오프셋 사용`

위 예시는 컬럼과 값의 형식만 보여주는 짧은 예시입니다. 실제 모델 학습에는 최소 90일의 데이터가 필요하며 180일 이상을 권장합니다.

## 3. 컬럼별 규칙

### `timestamp`

- 각 행이 나타내는 **1시간 소비 구간의 시작 시각**입니다.
- 분, 초, 마이크로초는 모두 0이어야 합니다.
- 정상 예: `2026-01-01 09:00:00`, `2026-01-01T09:00:00+09:00`
- 오류 예: `2026-01-01 09:30:00`, `2026/13/40 25:00`
- 같은 실제 시각을 두 번 입력할 수 없습니다.
- 오프셋 포함 시각과 오프셋 없는 시각을 한 파일에서 섞지 않습니다.
- 시각을 역순으로 입력하거나 중간 행의 순서를 바꾸지 않습니다.

누락된 시간이 있다면 없는 행을 임의의 0값으로 만들지 마세요. 실제 행만 유지하면 시스템이 누락 구간을 품질 진단에서 계산합니다. 다만 전체 누락률이 5%를 초과하거나 연속 누락이 24시간을 초과하면 학습 자격은 `FAIL`입니다.

### `kwh`

- 해당 1시간 동안 소비한 전력 에너지량입니다.
- 0 이상의 유한한 숫자만 입력합니다.
- 정상 예: `0`, `0.0`, `12`, `12.375`
- 오류 예: 빈 값, `-1.2`, `NaN`, `Inf`, `12kWh`, `1,234.5`
- 소수점에는 마침표(`.`)를 사용합니다.
- 순간 전력 `kW`나 누적 검침값을 컬럼명만 바꾸어 입력하면 안 됩니다.

## 4. 업로드 화면에서 함께 입력할 값

### 건물 ID

건물과 저장 모델을 구분하는 식별자입니다.

- 허용 문자: 영문, 숫자, 밑줄(`_`), 하이픈(`-`)
- 정상 예: `office-main`, `building_01`
- 오류 예: `본사 건물`, `office/main`, `office 01`

### 건물의 시간대

IANA 시간대 이름을 사용합니다.

- 한국: `Asia/Seoul`
- 미국 뉴욕: `America/New_York`
- 영국 런던: `Europe/London`
- UTC: `UTC`

`KST`, `EST`, `CST`처럼 의미가 모호한 약어는 사용하지 않습니다.

DST가 있는 지역에서는 오프셋 없는 현지 시각이 중복되거나 존재하지 않을 수 있습니다. 이 경우 각 행에 `-04:00`, `-05:00` 같은 실제 UTC 오프셋을 포함하고 `CSV에 포함된 UTC 오프셋 사용`을 선택하는 방법이 가장 안전합니다.

## 5. 품질 판정에 필요한 기간

| 관측 기간 | 결과 | 의미 |
|---|---|---|
| 90일 미만 | `FAIL` | 모델 학습 불가 |
| 90~179일 | `WARNING` | 명시적 동의 후 제한 실험 가능 |
| 180일 이상 | 기간 기준 `PASS` 후보 | 다른 품질 기준도 함께 충족해야 함 |

180일 분량을 매시간 기록하면 일반적으로 4,320개 행입니다. DST 전환이나 실제 누락이 있는 경우 행 수만으로 기간과 연속성을 판단하지 않으며, 시스템이 실제 시각을 기준으로 검사합니다.

## 6. 자주 발생하는 오류

| 오류 상황 | 해결 방법 |
|---|---|
| 필수 컬럼 누락 | 첫 행에 `timestamp,kwh`를 정확히 입력 |
| CSV를 읽을 수 없음 | UTF-8 CSV로 다시 저장하고 헤더 확인 |
| 비어 있는 값 | 원본 계측값을 확인하고 임의로 0을 채우지 않음 |
| 음수 또는 문자 kWh | `kwh`를 0 이상의 숫자로 준비 |
| 30분 또는 불규칙 간격 | 1시간 단위 원본 데이터를 사용 |
| timestamp 중복 | 같은 실제 시각의 중복 행을 원본에서 확인 |
| timestamp 순서 오류 | 오래된 시각부터 오름차순으로 준비 |
| 시간대 형식 혼용 | 모든 행을 오프셋 포함 또는 미포함 중 한 방식으로 통일 |
| 누적 검침값 | 각 시간 구간의 소비량 kWh 데이터로 별도 준비 |
| 잘못된 건물 ID | 영문·숫자·밑줄·하이픈만 사용 |

## 7. 업로드 전 최종 체크리스트

- [ ] 파일 확장자가 `.csv`이고 크기가 25MB 이하이다.
- [ ] UTF-8로 저장했다.
- [ ] 첫 행이 정확히 `timestamp,kwh`이다.
- [ ] 한 파일에 건물 한 곳의 데이터만 있다.
- [ ] timestamp가 1시간 구간의 시작 시각이다.
- [ ] timestamp의 분과 초가 `00`이다.
- [ ] timestamp가 중복 없이 오름차순이다.
- [ ] 모든 kWh 값이 비어 있지 않은 0 이상의 숫자이다.
- [ ] kWh가 누적 검침값이나 kW가 아닌 시간 구간 소비량이다.
- [ ] 건물 ID와 시간대 설정이 실제 데이터와 일치한다.
- [ ] 최소 90일, 가능하면 180일 이상의 데이터를 준비했다.

시스템은 오류를 숨기기 위해 행을 삭제하거나 값을 보간하지 않습니다. 오류가 발생하면 표시된 원인과 원본 계측 기록을 확인한 뒤 수정한 CSV를 다시 업로드하세요.
