# Energy Planner 제품 요구사항 문서(PRD)

## 1. 문서 목적

이 문서는 `docs/mvp.md`의 제품 방향과 이후 승인된 데이터·학습 정책, 현재 구현 상태를 제품 요구사항으로 정리합니다. 초기 MVP 문서의 미확정 항목은 후속 명세에서 확정된 경우 최신 정책을 따릅니다.

상태 표기:

- **구현됨**: 코드와 자동 검증이 존재함
- **부분 구현**: 핵심 경로는 있으나 운영 요건 또는 실제 UI 검증이 부족함
- **미구현**: 요구사항만 존재함
- **미검증**: 구현 여부와 별개로 실제 환경 검증이 완료되지 않음

## 2. 제품 목표

사용자가 건물 한 곳의 시간당 구간 소비량 CSV를 업로드하면 데이터 품질과 학습 자격을 진단하고, 건물 전용 XGBoost와 Last-24h·Last-168h 기준 모델을 공정하게 비교하여 선택된 모델로 향후 24시간 전력 사용량을 예측합니다.

제품은 XGBoost가 항상 우수하다고 가정하지 않으며, Validation에서 모델을 선택하고 Test는 독립 최종 평가에만 사용합니다.

## 3. 주요 사용자

- 건물의 다음 24시간 전력 사용량을 확인하려는 운영 담당자
- 보유 CSV가 모델 학습에 적합한지 확인하려는 데이터 담당자
- 데이터 검증부터 모델 저장·재사용까지의 AI 서비스 과정을 평가하려는 사용자

## 4. 핵심 사용자 흐름

1. 사용자가 건물 ID, 시간대와 시간대 해석 방식을 입력하고 CSV를 선택합니다.
2. 시스템이 CSV 계약과 품질을 검사해 PASS/WARNING/FAIL 및 사유를 표시합니다.
3. 학습 자격이 있으면 사용자가 별도 학습 작업을 요청합니다.
4. 시스템이 시간순 분할, XGBoost 학습과 baseline 비교를 수행합니다.
5. Validation 기준으로 후보를 고정한 뒤 Test 성능을 한 번 평가합니다.
6. 불변 run에 모델·스케일러·명세·평가 결과를 저장합니다.
7. 일반 예측 요청은 저장된 선택 모델을 재사용하며 자동 재학습하지 않습니다.
8. 화면은 24시간 예측, 총사용량, 피크와 모델 정보를 표시합니다.

## 5. 기능 요구사항

### PRD-F01 CSV 입력 — 구현됨

- CSV 한 개는 건물 한 곳만 나타냅니다.
- 필수 컬럼은 `timestamp`, `kwh`입니다.
- UTF-8 텍스트와 25MB 이하 파일을 처리합니다.
- 화면은 파일명·크기와 품질 진단 후 인식 컬럼·행 수를 표시합니다.
- `kwh`는 누적 검침값이 아닌 해당 한 시간 구간의 소비 에너지량입니다.
- 원본 값을 자동 보간·삭제·보정하지 않습니다.

### PRD-F02 시간대 입력과 정규화 — 구현됨

- 일반 현지시각, 명시적 UTC offset, BDG2 고정 표준시 모드를 구분합니다.
- UTC 기준 중복, 정렬과 시간 간격을 검사합니다.
- BDG2 고정 격자는 실제 민간시각 DST 복원으로 해석하지 않습니다.

### PRD-F03 데이터 품질 진단 — 구현됨

- 필수 컬럼, timestamp, NaN·Inf·음수, 중복과 시간 간격을 검사합니다.
- 관측 기간, 결측률, 최대 연속 결측, 0값, 이상치 의심값을 산출합니다.
- 장기 상수 구간, 지배값 비율과 상태 전환 의심을 경고합니다.
- Train 0분산은 `FAIL_TRAIN_ZERO_VARIANCE`로 학습 전에 차단합니다.
- 최신 168시간이 불완전하면 최신 XGBoost 예측을 허용하지 않습니다.

### PRD-F04 학습 자격 — 구현됨

- 90일 미만은 FAIL입니다.
- 90~179일은 명시적 승인이 필요한 WARNING 제한 실험입니다.
- 180일 이상은 기본적으로 Validation/Test 각 30일을 확보합니다.
- 최소 표본 1,000/168/12/12 기준을 적용합니다.
- 전체 기간만으로 자격을 판단하지 않고 각 분할의 유효 조합을 검사합니다.

### PRD-F05 시간순 분할과 누수 방지 — 구현됨

- 입력은 `T-167`부터 `T`, 정답은 `T+1`부터 `T+24`입니다.
- Train 타깃은 Train, Validation 타깃은 Validation, Test 타깃은 Test 안에 있어야 합니다.
- 경계 이전의 관측 완료 데이터는 Validation/Test 입력 문맥으로 사용할 수 있습니다.
- 스케일러는 Train 고유 timestamp에만 적합합니다.
- Test는 모델·피처·하이퍼파라미터 선택에 사용하지 않습니다.

### PRD-F06 건물별 신규 XGBoost 학습 — 구현됨

- 입력은 `[B,168,6]`, 출력은 `[B,24]`입니다.
- 피처는 `kwh`, `hour_sin`, `hour_cos`, `weekday_sin`, `weekday_cos`, `is_weekend`입니다.
- 기존 GRU 가중치를 재사용하지 않고 건물별 XGBoost 모델을 새로 학습합니다.
- CPU 기본 설정과 seed 42로 재현 가능한 학습을 수행합니다.

### PRD-F07 baseline과 모델 선택 — 구현됨

- Last-24h와 Last-168h를 동일한 비중복 평가창에서 비교합니다.
- Validation MAE가 작은 baseline을 최우수 baseline으로 정합니다.
- XGBoost 승격 후보 기준은 승인된 MAE·RMSE·WAPE 및 유한·비음수 조건을 따릅니다.
- 기준을 만족하지 못하면 최우수 baseline을 선택할 수 있습니다.
- Test 결과로 후보를 다시 선택하지 않습니다.

### PRD-F08 불변 산출물 — 구현됨

- 건물 ID와 run ID로 산출물을 격리합니다.
- 모델·스케일러·학습 설정·피처·분할·평가 일정·지표·해시를 저장합니다.
- 기존 run을 덮어쓰지 않습니다.
- `active_model.json` 승격은 학습과 분리하며 현재 자동 승격하지 않습니다.

### PRD-F09 저장 모델 예측 — 구현됨

- 완료된 run의 선택 모델만 재사용합니다.
- 출력은 24개의 유한한 비음수 kWh여야 합니다.
- 총사용량, 피크값, 피크 시각과 run·모델 정보를 반환합니다.
- 24시간 총량·평균·최대·피크 시각과 최근 24시간·7일·월별 실제 사용량 요약을 표시합니다.
- 예측 요청 중 재학습하지 않습니다.

### PRD-F10 로컬 웹 화면 — 구현됨

- 단일 페이지 `/`에서 Hero → CSV 업로드 → 품질 진단 → 모델 학습 → 예측 대시보드 순서로 이동하며, URL hash로 각 섹션을 직접 연결합니다.
- CSV 선택, 자동 건물 ID·시간대 입력과 품질 결과를 제공합니다.
- 학습 작업의 QUEUED/RUNNING/COMPLETED/FAILED 상태를 표현합니다.
- Validation MAE, 선택 모델과 run ID를 표시합니다.
- 저장 run 예측 후 그래프·총량·피크를 갱신합니다.
- Editorial 기반 Wave Halftone 랜딩과 파란색 계열 작업 화면을 사용합니다.
- 실제 Chrome에서 데스크톱 1440px, 모바일 390px·320px 흐름과 스크린샷을 검증했습니다.

### PRD-F11 선택형 AI 예측 해석 — 부분 구현

- 사용자가 실제 24시간 예측 후 명시적으로 요청할 때만 OpenAI API를 호출합니다.
- 원본 CSV 전체가 아니라 24개 예측값과 최소 집계 정보만 전송합니다.
- API 키는 서버 환경변수에서만 읽고 화면·health 응답에 노출하지 않습니다.
- API 키 누락·timeout·거부·형식 오류가 기본 예측 결과에 영향을 주지 않습니다.
- 실제 API 키를 사용한 외부 호출은 미검증이며 mock·비활성 상태만 검증됐습니다.

## 6. 비기능 요구사항

- 원본 BDG2, 기존 인턴 모델과 기존 불변 run을 수정하지 않습니다.
- 사용자 CSV와 모델 파일을 공개 소스에 포함하지 않습니다.
- 비밀키와 개인정보를 로그·화면·산출물에 노출하지 않습니다.
- 로컬 서버는 기본적으로 `127.0.0.1`에만 바인딩합니다.
- 실패를 성공으로 표시하거나 예측값을 임의 보정하지 않습니다.

## 7. 현재 구현 한계

- 완료 job 메타데이터는 로컬 artifact 아래에 저장돼 서버 재시작 후 복구됩니다. 재시작 당시 QUEUED/RUNNING 작업은 자동 재개하지 않고 FAILED로 전환합니다.
- 인증, CSRF 방어와 사용자별 데이터·artifact 권한 격리가 없습니다.
- 업로드 파일과 산출물 보존·삭제 정책이 확정되지 않았습니다.
- 상용 규모 다중 사용자와 분산 학습을 지원하지 않습니다.
- OpenAI 실제 호출은 유효한 사용자 키로 별도 검증이 필요합니다.
- 운영 모델 승격·롤백 정책은 설계됐지만 실행 승인이 필요합니다.

## 8. MVP 제외 범위

- 실시간 계량기·한전 계정 연동
- 공통 모델, 자동 튜닝과 예측 시 자동 재학습
- 기상 API, 전기요금 계산과 자동 설비 제어
- 딥러닝 모델 학습, 결제, 알림과 관리자 화면
- 외부 배포 및 상용 규모 동시 학습

## 9. 완료 기준

- PRD-F01~F09가 자동 테스트와 실제 산출물로 검증돼야 합니다.
- PRD-F10은 실제 브라우저 데스크톱·모바일 QA가 완료돼야 완전 구현으로 판정합니다.
- 정상·오류 CSV, 학습 성공·실패, 저장 run 예측 기록이 남아야 합니다.
- Test 독립성, 건물 격리와 파일 무결성이 검증돼야 합니다.

## 10. 미결정 사항

- 사용자·건물 식별 및 인증 방식
- job 영속화와 재시작 복구 방식
- 업로드·모델 보존 기간과 삭제 정책
- 운영 모델 승격·롤백 승인 절차
- 배포 환경과 자원 제한
