## 2. 구현 범위

다음 흐름을 독립적인 Python ML 백엔드로 구현했다.

`UTF-8 CSV → 계약 검사 → UTC 정규화 → 품질 진단 → 적응형 시간 분할 → 6개 피처 → 168→24 시퀀스 → Train 전용 스케일링 → GRU 학습 → Validation baseline 비교 → 후보 고정 → Test 1회 평가 → 불변 산출물 저장 → 저장 run 재사용 추론`

주요 정책은 다음과 같다.

- 입력 피처 순서: `kwh`, `hour_sin`, `hour_cos`, `weekday_sin`, `weekday_cos`, `is_weekend`
- 입력/출력: `[B,168,6] → [B,24]`
- 90일 미만은 FAIL, 90~179일은 명시적 승인 없이는 학습 차단, 180일 이상은 30일 Validation/Test 적용
- Validation/Test의 입력은 예측 시점 이전 실제 관측 문맥을 공유할 수 있으나 타깃은 각 분할 안에 완전히 포함
- 입력·타깃 스케일러는 Train 고유 timestamp만 사용하여 적합
- Validation 비중복 24시간 구간에서 GRU, Last-24h, Last-168h 비교
- baseline MAE 동률은 필요한 과거 이력이 짧은 Last-24h 우선
- WAPE 분모가 0이면 비교 불가로 기록하고 GRU를 이 조건의 생략으로 승격하지 않음
- 음수·비유한 GRU 예측은 보정하지 않고 후보에서 제외
- Test 결과는 후보 재선택에 전달되지 않음
- run 디렉터리는 덮어쓰지 않으며 파일별 SHA-256과 건물 ID를 검증
- baseline이 선택돼도 해당 실험의 GRU 후보·입력 스케일러·타깃 스케일러를 감사용으로 보존
- 일반 추론은 명시된 run만 로딩하며 학습·스케일러 재적합을 호출하지 않음

## 5. 초기 실패와 해결 내역

1. 첫 자동 검증에서 Pandas 3의 datetime 저장 단위가 마이크로초일 수 있음을 고려하지 않아 정상 1시간 간격을 오인했다. 검사 전에 DatetimeIndex를 나노초 단위로 명시 변환해 정수 배수로 비교하도록 수정했다.
2. 첫 벤치마크에서 Windows 프로세스 핸들을 32비트 반환형으로 해석해 메모리 측정이 학습 전에 실패했다. `ctypes`의 반환형과 인자형을 64비트 포인터 기준으로 명시했다.
3. 수정 후 전체 15개 검증과 종단 간 벤치마크를 다시 실행했으며 최종 실패는 0개다.

## 7. CPU 실행 시간과 메모리

90일 완전 합성 데이터와 승인 기본 설정을 사용해 전체 파이프라인을 실제 실행했다.

| 항목 | 측정값 |
|---|---:|
| Train 시퀀스 | 1,249개 |
| 최적 epoch / 중단 epoch | 33 / 40 |
| 전체 파이프라인 시간 | 83.484초 |
| 저장 run 재사용 추론 시간 | 0.0199초 |
| Peak working set | 465,784,832 bytes (약 444.2 MiB) |
| 종료 시 working set 증가 | 122,978,304 bytes (약 117.3 MiB) |
| 입력 / 출력 shape | `[1,168,6]` / `[1,24]` |

합성 데이터는 정확한 일·주 주기를 갖도록 생성했기 때문에 Last-168h가 Validation에서 선택됐다. 이는 모델 선택 로직의 기대 동작을 확인하는 결과일 뿐 GRU 일반화 성능 비교 근거가 아니다.

## 8. 모델 평가와 산출물 관리

- Validation에서 Last-24h와 Last-168h 중 MAE가 낮은 baseline을 먼저 확정한다.
- GRU는 baseline 대비 MAE 5% 이상 개선, RMSE·WAPE 각각 5% 초과 악화 없음, 유한·비음수 조건을 모두 만족할 때만 선택한다.
- 후보 확정 뒤 Test에서는 해당 후보 하나만 평가하며 순위가 바뀌어도 재선택하지 않는다.
- run에는 설정, 피처, 분할, 동결 평가 일정, 품질, Validation/Test 지표, 학습 이력, GRU 후보와 스케일러 및 파일 해시를 저장한다.
- `model_kind`는 실제 선택된 예측기를 나타내므로 baseline도 향후 승인 절차를 거쳐 활성 예측기로 사용할 수 있다.
- 저장 경로에 같은 건물 ID·run ID가 있으면 덮어쓰지 않는다.
- `active_model.json` 변경, candidate 자동 승격, 자동 롤백은 구현하지 않았다.

## 9. 남은 위험과 미확정 사항

실제 Office 학습 전에 PM 검토가 필요한 항목은 다음과 같다.

1. 1,000/168/12/12 최소 표본 기준은 아직 잠정값이다.
2. IQR 기반 이상치 개수는 진단용 휴리스틱이며 학습 제외나 값 보정에 사용하지 않았다.
3. CSV 값만으로 구간 kWh와 누적 검침값 또는 kW를 확실히 식별할 수 없다. 업로드 메타데이터·사용자 확인 정책이 필요하다.
4. 오프셋 없는 현지시각의 DST 중복·존재하지 않는 시각은 현재 안전하게 거부한다. 사용자 오류 안내와 재업로드 흐름은 API 단계에서 설계해야 한다.
5. 재학습 조건, run·원본 보존 기간, 수동 승격·롤백 권한은 미확정이다.
6. CPU 측정은 현재 PC와 합성 90일 데이터에 한정되며 180일·365일 및 실제 Office 데이터 자원 사용량은 아직 측정하지 않았다.
7. 실제 Office 데이터에서 품질 통과, 단위 의미, 분포, 정확도 및 음수 예측 가능성을 별도로 검증해야 한다.
