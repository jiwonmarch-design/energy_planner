## 변경 파일과 주요 로직

- `frontend/index.html`
  - 선택 파일 카드, 파일 변경·선택 취소 버튼
  - 시간대 자동완성 목록과 시간 해석 필드 오류 영역
  - 진단 전 품질 요약과 접근성 속성
- `frontend/app.js`
  - 파일 교체·취소 시 종속 상태 초기화
  - 진단 요청 ID와 입력 서명으로 오래된 응답 무시
  - API 오류의 사용자용 한국어 매핑
  - PASS/WARNING/FAIL 및 단계 이동 상태 처리
- `frontend/editorial-workspace.css`
  - 선택 파일 카드, 필드 오류, 품질 사전 요약 스타일
  - 390px·320px 파일 카드와 긴 제목의 모바일 잘림 수정
- `analysis/phase9_web_qa/ux_implementation/`
  - Chrome CDP QA 스크립트, 합성 전용 fixture, 결과 JSON, 스크린샷

백엔드 API, ML 코드, 모델 학습·예측 로직은 변경하지 않았다.

## 사용자가 보는 변경

- 파일 선택 전: 큰 드롭존과 비활성 품질 진단 버튼을 표시한다.
- 파일 선택 후: 드롭존 대신 파일명·크기·현재 전송 상태와 `파일 변경`, `선택 취소`를 표시한다.
- 선택 취소: 브라우저 파일 input, 진단 결과, 동의, 오류와 학습 가능 상태만 초기화한다. 저장 모델과 학습 기록은 삭제하지 않는다.
- 오프셋 없는 CSV를 `CSV에 포함된 UTC 오프셋 사용`으로 진단하면 다음을 표시한다.
  - `CSV에 UTC 오프셋이 포함되어 있지 않습니다.`
  - `‘시간대 정보가 없는 현지 시각’을 선택하고 다시 진단해 주세요.`
- 시간대는 서울·뉴욕·도쿄·런던 등 자주 쓰는 도시 또는 IANA 식별자로 자동완성할 수 있다.

## 남은 리스크와 제약

- `선택 취소`는 브라우저가 보유한 CSV와 그에 종속된 임시 UI 상태만 지운다. 서버 artifact·저장 모델 영구 삭제 API는 구현하지 않았다.
- 브라우저 보안상 전체 새로고침 후 로컬 파일 선택은 복원할 수 없으므로 CSV를 다시 선택해야 한다.
- 시간대 자동완성은 서버 시간대 목록 API가 없어 자주 쓰는 항목을 제공하는 `datalist` 대안이다. 임의 입력은 브라우저에서 먼저 확인하고 서버 검증을 최종 기준으로 사용한다.
- 서버 학습 job은 메모리 기반이므로 서버 재시작 후 완전 복구되지 않는다.
- 건물 ID는 여전히 식별 키이며 계정·권한 체계가 아니다. 로그인, 사용자별 건물 목록과 영구 삭제는 별도 설계·승인이 필요하다.
- 네이티브 시간대 자동완성 목록의 실제 키보드·터치 조작 감각은 브라우저/OS별 수동 QA가 추가로 필요하다.

## 추가 의사결정 필요 사항

- 서버가 제공하는 전체 IANA 시간대 검색 API 도입 여부
- 인증·사용자별 건물 및 artifact 접근 제어
- 업로드 원본과 모델 artifact의 보존·영구 삭제 정책
- 서버 재시작 후 학습 job 영속화 방식
