## 1. 범위와 판정

- 대상 run: `Hog_office_Leon / 20261030T024644Z_phase7-2_a6-v1`
- 분석 성격: **사후 탐색 분석**. 새로운 성능 검증이나 모델 재선택이 아니다.
- 실행 행위: 저장된 가중치와 두 scaler를 읽어 기존 고정 평가 일정의 예측만 재현했다.
- 금지 사항 준수: 재학습, 하이퍼파라미터 변경, 평가 날짜 변경, Test 기반 재선택, run·manifest 수정, 활성 모델 변경을 하지 않았다.

## 4. 확인된 원인과 가능한 가설

### 확인된 원인 수준의 사실

- **부하 수준 이동:** Test 평균·중앙값·하위 분위가 Validation보다 높고 GRU 과소추정 편향이 확대됐다.
- **평가 구간 구성 차이:** Test는 12월이며 크리스마스 전후의 평탄한 특수 운영일과 높은 평일 부하일을 함께 포함한다. Validation에는 11월 23일의 평탄한 저부하일이 포함된다.
- **최근 패턴 반복성:** 12월 24일과 31일은 Last-24h/168h MAE가 0.10~0.18kWh인 반면 GRU는 1.22~1.24kWh다. 단순 반복 baseline이 해당 구간의 안정된 패턴을 더 잘 따라갔다.
- **고부하일 과소추정:** 12월 11일(실측 최대 17.5kWh)과 13일(15.2kWh)의 GRU 피크 크기 오차는 각각 -6.143, -4.338kWh였다.

### 가능한 가설 — 인과관계는 확인하지 않음

- Train/Validation보다 높아진 12월 기저부하에 대해 GRU가 학습 분포 쪽으로 수축했을 가능성.
- 6개 피처에 공휴일·운영 일정 정보가 없어 11월 23일과 12월 25일 같은 특수일을 평일로 처리한 영향 가능성.
- Last-168h가 12월 후반 반복 운영 패턴을 직접 복사해 유리했을 가능성.
- 데이터 기간이 단일 180일이고 Test가 단일 월이므로 계절 변화와 달력 효과가 혼재했을 가능성.

이 가설들은 관찰적 연관이다. 현재 결과만으로 특정 피처나 학습 설정이 역전의 단일 원인이라고 단정할 수 없다.

## 6. BDG2 시간대 처리 감사

### 원본 격자와 현재 처리

- BDG2 cleaned CSV는 오프셋이 없는 매시간 시각 라벨을 사용하고, 2016~2017 전체 격자는 DST 중복·누락 없이 연속된다. 메타데이터의 Leon timezone은 `US/Central`이다.
- Phase 7-2는 이 라벨을 보존하기 위해 `Etc/GMT+6` 고정 표준시로 현지화한 뒤 UTC로 변환했다. 따라서 6개 시간·요일 피처는 run 내부 규칙과 일관된다.
- 같은 UTC 시각을 `America/Chicago`로 해석하면 4,320시간 중 2,953시간의 hour와 123시간의 weekday가 현재 고정 표준시 피처와 달라진다. `America/Chicago`는 이 기간에 UTC-5와 UTC-6을 모두 사용하지만 `Etc/GMT+6`은 항상 UTC-6이다.

현재 변환은 BDG2의 균일한 원본 라벨을 보존하는 **데이터셋 전용 규칙**으로는 적합하지만 실제 미국 민간시각의 DST 의미를 복원한다고 볼 수 없다. 반대로 실서비스의 offset-aware CSV 또는 IANA 시간대가 지정된 naive CSV는 실제 DST 규칙을 적용해야 하므로 BDG2 규칙과 분리해야 한다.

### 다음 manifest 필수 명세 권고

```json
{
  "source_timezone_mode": "bdg2_naive_local_grid_fixed_standard",
  "source_timezone_metadata": "US/Central",
  "feature_timezone": "Etc/GMT+6",
  "dst_applied": false,
  "utc_offset_hours": -6,
  "timestamp_semantics": "source_hour_label",
  "timezone_interpretation_warning": "BDG2 fixed grid; not civil-time DST reconstruction"
}
```

실서비스에는 별도 값 `iana_civil_time` 또는 `explicit_offset`을 사용하고, 모드별 처리 함수를 섞지 않는 것이 안전하다.

## 8. PM 판단 요청

1. Leon 후보는 Validation 선택 결과를 그대로 유지하고 Test 역전은 일반화 위험으로 기록한다.
2. `source_timezone_mode`를 다음 실제 학습 run부터 manifest 필수 필드로 추가하는 구현 변경을 승인한다.
3. 공휴일 피처 추가나 하이퍼파라미터 변경은 이번 사후 분석으로 자동 승인하지 않는다. 여러 건물 결과를 확보한 뒤 별도 실험 설계로 판단한다.
