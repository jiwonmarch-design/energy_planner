01

시간별 CSV를 준비합니다

한 파일에는 한 건물의 데이터만 넣습니다. 첫 행에는 timestamp와 kwh가 필요합니다.

timestamp1시간 구간의 시작 시각 · ISO 8601 권장
kwh해당 한 시간의 소비 에너지량 · 0 이상의 유한값
  • 관측 간격은 정확히 1시간이어야 합니다.
  • 최소 90일, 안정적인 비교를 위해 180일 이상을 권장합니다.
  • 추가 열은 허용하지만 현재 모델 학습에는 사용하지 않습니다.
  • 누적 검침값이나 순간 전력 kW는 입력할 수 없습니다.
02

데이터 품질을 진단합니다

파일 형식, 누락된 시간, 장기 상수 구간과 최신 168시간의 완전성을 확인합니다. 원본값을 자동으로 보간하거나 0으로 바꾸지 않습니다.

PASS는 학습 가능, WARNING은 위험 확인과 명시적 동의 필요, FAIL은 원본 데이터 보완이 필요하다는 뜻입니다.

03

XGBoost와 기준 모델을 비교합니다

학습 버튼을 눌렀을 때만 건물 전용 XGBoost를 새로 학습합니다. 같은 Validation 구간에서 XGBoost, 전날 동일 시각, 지난주 동일 시각 예측을 비교합니다.

  • Train → Validation → Test 순서의 시간 분할을 유지합니다.
  • Validation으로 모델을 선택하고 Test는 최종 확인에만 사용합니다.
  • 예측 요청은 저장 모델을 재사용하며 자동 재학습하지 않습니다.
04

향후 24시간 예측을 확인합니다

Dashboard에서 총사용량, 평균 시간당 사용량, 최대 사용량과 피크 시각을 확인합니다. 과거 실측선과 미래 예측선은 서로 다른 선 모양과 범례로 구분됩니다.

예측값은 계획을 돕는 추정치이며 실제 계측값을 보장하지 않습니다.

05

선택적으로 AI 해석을 요청합니다

OpenAI API가 설정된 로컬 서버에서는 예측 후 사용자가 직접 ‘AI 분석하기’를 누를 수 있습니다. AI는 수치를 예측하지 않고 이미 생성된 결과를 설명합니다.

  • 원본 CSV 전체는 OpenAI API로 전송하지 않습니다.
  • API 키가 없거나 호출에 실패해도 기본 예측 결과는 유지됩니다.
  • 날씨·설비 상태처럼 제공되지 않은 원인은 단정하지 않습니다.
FAQ

자주 발생하는 문제

시간대는 무엇을 선택해야 하나요?

건물이 위치한 도시의 IANA 시간대를 선택합니다. 예를 들어 한국은 Asia/Seoul입니다. timestamp에 UTC 오프셋이 있으면 서버가 이를 우선 해석합니다.

90일 미만 데이터가 거부되는 이유는 무엇인가요?

168시간 입력과 독립적인 Validation·Test 구간을 충분히 확보할 수 없기 때문입니다. 원본 계측 기간을 늘린 뒤 다시 진단하세요.

학습 중 페이지를 이동해도 되나요?

같은 서버가 실행 중이면 학습은 백그라운드에서 계속됩니다. 새로고침 후 저장된 작업 ID로 상태를 다시 조회합니다. 서버 자체가 재시작되면 진행 중 학습은 실패로 표시하고 자동 재시작하지 않습니다.

AI 분석 버튼이 비활성화되어 있습니다.

먼저 24시간 예측을 실행해야 하며, 서버에 OPENAI_API_KEY가 설정되어 있어야 합니다. AI 해석이 없어도 예측 기능은 정상 작동합니다.
